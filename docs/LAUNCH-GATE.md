### Why there are 0 approved facts

By design, not by fault. CLAUDE.md §2.1: nothing may be set to `approved` in code, fixtures or seed scripts;
approval happens **only in the CMS, by the company secretary (corporate) or competent person (technical)**. The CMS
has no project yet, so there is nowhere to approve anything. Every value we hold came from the old website
(`CONTENT-SOURCE.md`: "Nothing here is verified") and is stored as `toVerify`; everything else is INPUT NEEDED.

Consequence: **there is no launch path that skips Sanity.** The fixtures can never produce a single approved fact,
so the CMS (Q-10, Q-45) is on the critical path, not a later nice-to-have.

### 3.4 Hosting and deployment (proposed architecture for A-5)

Implemented on the repository side in `docs/DEPLOYMENT.md` (D-034), with two refinements: the deploy workflow is
manual only (no webhook yet), and the production Worker has no workers.dev address or committed route, so it serves
nothing until its custom domain is attached at cutover. The sketch below is kept as written.

```
GitHub (main) ── Actions ──▶ build (CONTENT_SOURCE=sanity, dataset production, published perspective, SANITY_READ_TOKEN)
                             ├─ guards, e2e, budget, readiness artifact
                             └─ wrangler deploy            ──▶ Worker auburn-edge + static assets (dist)
                                                                auburnresources.com.au (+ www → apex)
                 ──▶ build:preview (drafts perspective)    ──▶ Worker auburn-edge-preview (dist-preview)
                                                                preview.auburnresources.com.au, behind Access
Sanity publish ── webhook ──▶ repository_dispatch ──▶ same workflow
```

- Secrets: `SANITY_READ_TOKEN`, `CLOUDFLARE_API_TOKEN` (GitHub); webhook secret/token (Sanity). Non-secret:
  `CLOUDFLARE_ACCOUNT_ID`, `SANITY_PROJECT_ID`, `SANITY_DATASET`, `SITE_URL`. Later: Turnstile, Postmark, ESP.
- Redirects and headers: already generated per build (`_redirects`, `_headers`, Worker headers). Caching:
  `/_astro/*` immutable; HTML revalidates per deploy (verify, E-8).
- Preview: `dist-preview` is `noindex` + `Disallow: /`, but **only Access keeps it private** (C-3).
- DNS: C-6; cut-over after E-1–E-8 pass on the preview host with production content.
